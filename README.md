# Focus List

Build a Functional To-Do Application

Build a frontend-only To-Do application called FocusList within 1 hour. The application should allow users to create and manage their daily tasks through a simple and responsive interface. REQUIRED FEATURES: 1. Task Creation Users must be able to add a new task by entering a task title. 2. Task Management Users must be able to: - Mark tasks as completed - Edit existing tasks - Delete tasks 3. Task Priority Each task must have a priority: - High - Medium - Low The selected priority should be clearly visible for each task. 4. Search and Filtering Users must be able to: - Search tasks by title - Filter tasks by All, Active, and Completed - Filter tasks by priority Search and filters must update the displayed task list based on the underlying task data. 5. Task Statistics Display basic statistics such as: - Total Tasks - Completed Tasks - Pending Tasks These values should update when the task data changes. 6. Data Persistence Tasks should remain available after refreshing the page. Local Storage may be used for persistence. UI/UX REQUIREMENTS: - The interface should be clean and intuitive. - The application should be responsive across desktop and mobile devices. - Completed and pending tasks should be visually distinguishable. - Interactive controls should provide clear visual feedback. - The application should maintain consistent spacing, typography, and visual hierarchy. TECHNICAL CONSTRAINTS: - Frontend-only implementation is required. - No backend or server-side application logic. - No external database. - Local Storage is allowed. - Participants may use any frontend framework or vanilla HTML, CSS, and JavaScript. - A working live deployment is required. TIME LIMIT: Participants have 1 hour to build and submit their solution. Focus on completing the required functionality first, then improve the UI and overall experience if time permits. EVALUATION: The solution will be evaluated by the FAIE Evaluation System based on the configured requirements and technical checks, including functionality, UI/UX, responsiveness, code quality, accessibility, and performance. IMPORTANT: This is a demo/practice problem statement created to help participants understand the FAIE evaluation and submission process. The score obtained from this Demo Problem Statement will NOT be counted towards the main hackathon or the final leaderboard. The purpose of this challenge is to let participants experience the complete Build → Submit → FAIE Evaluation → Score workflow before the main hackathon.
